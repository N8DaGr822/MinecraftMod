Product requirements
- One regenerating resource block per team island in a void dimension; independent phase state per island.
- Separate islands for teams of up to six players; team roles and protection so visitors can travel but cannot mine other teams' generators or edit structures.
- Balanced survival, RPG, and automation: phases + objectives + encounter gates + machine upgrades.
- Future data-driven 12-phase roadmap, but MVP implements three phases: Genesis (250 breaks), Caverns (500 breaks), Verdant Wilds (600 breaks).
- Phase completion requires break threshold AND required objectives AND required encounters; post-threshold mining must not deadlock the generator.
- One Cave Guardian event, one collection upgrade, and one bounded auto-miner later in the MVP.
- Persistent teams/islands/generator/progression/bridge ownership/rewards; safe restart reconciliation and idempotent progress.
Hard island/bridge requirements — non-negotiable
Implement against the following design, replacing any older 1,024-block spacing assumption:
CARDINAL_CENTER_SPACING = 250 blocks
CLAIM_HALF_EXTENT       = 100 blocks on X and Z (square claim)
STARTER_PLATFORM        = 5 x 5 blocks at Y = 80
ISLAND_GRID_CENTER      = (gridX * 250, 80, gridZ * 250)
CARDINAL_NEIGHBORS     = cells exactly 1 apart along one grid axis
VISITOR_ENTRY           = allowed
VISITOR_BUILD           = denied
VISITOR_GENERATOR_USE   = denied
BRIDGE_CORRIDOR_WIDTH   = 7 block columns
BRIDGE_BUILD_Y_RANGE   = 72..96 (inclusive)
BRIDGE_TARGET           = must be an allocated cardinal-neighbor island
OFFLINE_AUTOMATION      = disabled
BRIDGE_CHUNK_LOADING    = disabled
The square claim test is abs(x-centerX) <= 100 && abs(z-centerZ) <= 100. Example: island A at (0,0) owns X -100..100; island B at (250,0) owns X 150..350; the neutral integer block columns are X 101..149 inclusive (49 columns; a 50-block geometric edge-to-edge distance). The E/W corridor is Z -3..3 along the gap; N/S is symmetric. 250 refers to center-to-center distance, not bridge length from a 5 x 5 starter platform.
Bridges must be player-built; never spawn automatic connections. Building within one's own claim follows team permissions. Building within the neutral zone is allowed only in a valid corridor between two allocated cardinal neighbors and within the allowed height band. Visitors may traverse bridges and enter other claims, but cannot alter protected claim blocks. Persist per-block team ownership of neutral bridge blocks, with a corridor ID, and protect against unauthorized breaking and supported explosion/piston/fluid/machine mutations. If a team or island is archived, remove only its own bridge blocks via a resumable cleanup job. Do not permit general-purpose building in the void outside these corridors. Neither bridges nor offline islands force chunks to stay loaded. Implement more invasive mod interoperability behind tested adapters; do not claim universal protection from every third-party mod.
Create a versioned config schema with these defaults. Treat changes to spacing/claim geometry on populated worlds as migration-required (reject hot reload, report why). Test the exact inclusive claim math and corridor cells.
Architecture and state invariants
- Domain model: TeamState, IslandState, GeneratorState, PhaseProgress, BridgeCorridorState, BridgeBlockOwnership, RewardLedger, UpgradeState, EncounterState.
- Core services: IslandService, TeamService, ProtectionService, BridgeService, GeneratorService, PhaseService, ObjectiveService, EncounterService, UpgradeService, PersistencePort.
- One confirmed eligible generator break => one and only one progress increment. Canceled, unauthorized, stale, and duplicate attempts => zero.
- Generator phases: READY, PENDING, REGENERATING, LOCKED, ERROR; idempotent regeneration by (islandId, generationIndex).
- Store persistent identifiers and a schema version. Use Minecraft SavedData or a compatible world data abstraction, selected after verifying the pinned loader API. On reload/restart reconcile world block vs. generator state without extra rewards or progress.
- Phase content is data-driven via validated JSON/datapacks. Content reload must preserve previous valid configuration when validation fails. Items/rewards require unique ledger IDs.
- Gameplay and world mutation occur on the correct server thread; clients are never authoritative over progress/ownership/rewards.
- common should not import Create or other optional external mod APIs directly; optional integrations live behind adapters.
