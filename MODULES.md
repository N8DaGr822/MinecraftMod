# Darkspawn modules (end of Stage 3)

Branch: `split-modular`. Gradle multi-project; every module lives in `modules/<name>` and applies the `darkspawn.fabric-module` convention plugin from `buildSrc/`.

Common to every module:
- Content namespace stays `darkspawn:` (ids, lang, tags, recipes unchanged). Mod id is `darkspawn_<name>`; Java packages are `darkspawn.black.<name without underscores>..` (no split packages).
- Requires Minecraft 26.3, Java 25, Fabric Loader ≥ 0.19.5 and Fabric API. Only `legacy` needs GeckoLib.
- `darkspawn_core` is nested (Fabric jar-in-jar) in every feature jar, so a server installs one jar per feature. Fabric Loader keeps one copy of core however many modules are installed.
- Version: `2.0.0-alpha.1` (root `gradle.properties`, unchanged).
- Jar: `modules/<name>/build/libs/<mod id>-2.0.0-alpha.1.jar` (sources jar next to it).
- Build one jar: `bash ./gradlew :<name>:playBuild --max-workers=1`.
- Unit tests: `bash ./gradlew :<name>:test --max-workers=1`.
- GameTests (standalone: that module + core + Fabric API only): `bash ./gradlew :<name>:runGameTest -PgameTestRunDir=<isolated dir with server.properties port ≥ 25600> --max-workers=1`. Use a separate run dir per module. Test ids are `darkspawn_<name>-gametest:<class>_<method>` in snake case.

## Still in `modules/legacy`

Everything not listed above: bosses and health/hearts (including boss essences and `EquipmentPowers`/`BossEmpowerment`), ecosystem (wildlife, hunts, regional events, world awakening/victory), cooking, farming, husbandry, fishing, culinary brewing, mounts and vehicles, Legacy of Noah, endgame Nexus and relics, worldgen/landmarks (including the expedition wreck structure and its loot), pirate seas, forsaken, OneBlock/Ascension, journal, testing camp and Dragon Starter Chest, audio/creature framework, data generation. Legacy no longer has an `equipment` package.

Legacy now calls core for: `Darkspawn.id/LOGGER/MOD_ID` (thin delegates), `ServerTuning` loading, sound registration, player save, payments, safe arrival, dragon gate, `Culinary.award` → `Progress.award`, and `ArmorGeometryRenderer` for the Noah (with its pulse texture) and quarantine armor. Hook registrations living in legacy: OneBlock registers the travel boundary (used by WolfHunt, RegionalEncounter, MountCompanions, NoahLegacy); OneBlock/Ascension fire `EquipmentChanged` (armor_styles and legendary_armor each listen); Cooking registers the WARMING meal as a climate provider; Pirate registers ward exemptions and its journal section; TaigaEcosystem and BossEntities register ward exemptions.

Cross-mod integration GameTests that need legacy content stay in legacy: `PirateBonfireWardGameTest`, `MountBonfireWardGameTest`, `BossHunterEnchantmentGameTest`, `oneblock.{Quiver,IngredientPouch,ExplorerPack}ProfileGameTest`, and `equipment.EquipmentIntegrationGameTest` (expedition suits with the WARMING meal, headlamp with meal vision, padded boots with boss/meal fall modifiers, style bonuses alongside a meal, styles and expedition gear with boss empowerment, style vs expedition conversion, legendary cores forged from boss essences). The testing camp (`TestingCamp`) still hands out expedition, legendary and styled armor from the modules.

## Working notes

- Module dependencies use the `modJar` outgoing configuration: `implementation module('core')` plus `include module('core')`. Consumers compile and run against the finished jar (main + client classes), the same shape as production.
- Root task names run in every module (`bash ./gradlew test`, `playBuild`, `fullCheck`). Pass `-PgameTestRunDir` only to a single module's `runGameTest`.
- Several jars now ship `assets/darkspawn/lang/en_us.json`, tag files and `assets/minecraft/atlases/blocks.json`. Unit tests that read those from the classpath must use `MergedResources.open` (legacy and storage have one).
- Mixins from different modules on the same target can change relative order. `ExpeditionArmorMixin` uses `priority = 900` so the headlamp's cancellable `getEffect`/`hasEffect` returns still run before legacy's meal-vision injector.
- Repo-level `tools/` scripts still point at `src/...` paths that moved to `modules/<name>/src/...`. Only `verify-cuisine-art.py` (used by `fullCheck`) is updated.
