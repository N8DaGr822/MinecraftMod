# Darkspawn modules (end of Stage 5)

Branch: `split-modular`. Gradle multi-project; every module lives in `modules/<name>` and applies the `darkspawn.fabric-module` convention plugin from `buildSrc/`.

Common to every module:
- Content namespace stays `darkspawn:` (ids, lang, tags, recipes unchanged). Mod id is `darkspawn_<name>`; Java packages are `darkspawn.black.<name without underscores>..` (no split packages).
- Requires Minecraft 26.3, Java 25, Fabric Loader ≥ 0.19.5 and Fabric API. `creature_kit`, `noah` and `legacy` also need GeckoLib (≥ 5.5.7, < 6), which is not nested; install it beside them.
- `darkspawn_core` is nested (Fabric jar-in-jar) in every feature jar, and the mount modules also nest `darkspawn_mount_kit`, so a server installs one jar per feature. Fabric Loader keeps one copy of each library however many modules are installed.
- Version: `2.0.0-alpha.1` (root `gradle.properties`, unchanged).
- Jar: `modules/<name>/build/libs/<mod id>-2.0.0-alpha.1.jar` (sources jar next to it).
- Build one jar: `bash ./gradlew :<name>:playBuild --max-workers=1`.
- Unit tests: `bash ./gradlew :<name>:test --max-workers=1`.
- GameTests (standalone: that module + core + Fabric API only): `bash ./gradlew :<name>:runGameTest -PgameTestRunDir=<isolated dir with server.properties port ≥ 25600> --max-workers=1`. Use a separate run dir per module. Test ids are `darkspawn_<name>-gametest:<class>_<method>` in snake case.

## Still in `modules/legacy`

Everything not listed above: bosses and health/hearts (including boss essences and `EquipmentPowers`/`BossEmpowerment`), boss cuisine (`boss.BossCuisine`: the 16 boss ingredients, 16 trophies and `TrophyBlock`, defeat rewards, heart progress, the winter-armor freeze guard), ecosystem (wildlife, hunts, regional events, world awakening/victory), endgame Nexus and relics, worldgen/landmarks (including the expedition wreck structure and its loot, and ocean notes through `ExplorationFishingMixin`), pirate seas, forsaken, OneBlock/Ascension, journal, testing camp and Dragon Starter Chest, `audio.DarkspawnSounds` (legacy's own sound events, including the encounter scores), data generation. Legacy keeps its rig list as `boss.CreatureRoster` (boss, mob and minion ids plus the texture-sheet helper) and registers mobs and minions with the creature kit. Legacy no longer has `equipment`, `cooking`, `mount` (main/client) or `legacy` (Noah) packages.

Legacy now calls core for: `Darkspawn.id/LOGGER/MOD_ID` (thin delegates), `ServerTuning` loading, sound registration, player save, payments, safe arrival, dragon gate, `Progress.award` (bosses call it directly; `Culinary.award` in cooking delegates to it), and `ArmorGeometryRenderer` for the Noah (with its pulse texture) and quarantine armor. Hook registrations living in legacy: OneBlock registers the travel boundary (used by WolfHunt, RegionalEncounter, mount_kit and Noah; Ascension levels report separate possessions); `RegionalEcosystems` registers a `Temperament` judge for `RegionalMob`; `BossEntities` registers boss bolt immunity for bosses and minions; `BiomeBoss` and `RegionalMob` implement `BossBolt.Shooter`; bosses, wildlife, Forsaken infected and the Ascension guardian implement the kit's render and audio hooks; Pirate registers relic-spared crew with Noah through `pirate.compat.NoahCompat`; OneBlock/Ascension fire `EquipmentChanged` (armor_styles and legendary_armor each listen); Pirate registers ward exemptions and its journal section; TaigaEcosystem and BossEntities register ward exemptions. The boss ingredient and trophy models use cooking's `cuisine_atlas` texture (legacy hard-depends on cooking today; a later bosses module needs its own copy or a hard cooking dependency).

Cross-mod integration tests that need legacy content stay in legacy: `PirateBonfireWardGameTest`, `MountBonfireWardGameTest`, `mount.MountCareGameTest` (aquatic capsules across the OneBlock boundary, Thalassar refused by the generic care menu), `mount.TravelMountGameTest` (mount abilities spare peaceful regional wildlife), `mount.MagicCarpetGameTest` and `mount.GroundWalkerGameTest` (capsule round trips that also check the Ascension dimension is excluded), `oneblock.AscensionGameTest` (Noah ledger isolation), `BossHunterEnchantmentGameTest`, `oneblock.{Quiver,IngredientPouch,ExplorerPack}ProfileGameTest`, `equipment.EquipmentIntegrationGameTest` (expedition suits with the WARMING meal, headlamp with meal vision, padded boots with boss/meal fall modifiers, style bonuses alongside a meal, styles and expedition gear with boss empowerment, style vs expedition conversion, legendary cores forged from boss essences), `food.CuisineIntegrationGameTest` (boss-ingredient dishes and scrolls, the cookbook's locked/unlocked pages, boss equipment powers, boss cuisine rewards), `food.ExpansionBrewingGameTest` (a brewing stand with farming's wild herbs), and the unit tests `food.CuisineTest` and `food.CookingRecipeTest` (decode every cooking recipe, including those that need farming or boss items). The testing camp (`TestingCamp`) still hands out food, fish, crops and brews from the modules.

## Working notes

- Module dependencies use the `modJar` outgoing configuration: `implementation module('core')` plus `include module('core')`. Consumers compile and run against the finished jar (main + client classes), the same shape as production.
- Root task names run in every module (`bash ./gradlew test`, `playBuild`, `fullCheck`). Pass `-PgameTestRunDir` only to a single module's `runGameTest`.
- Several jars now ship `assets/darkspawn/lang/en_us.json`, tag files and `assets/minecraft/atlases/blocks.json`. Unit tests that read those from the classpath must use `MergedResources.open` (legacy and storage have one).
- Mixins from different modules on the same target can change relative order. `ExpeditionArmorMixin` uses `priority = 900` so the headlamp's cancellable `getEffect`/`hasEffect` returns still run before cooking's meal-vision injector (`MealUtilityEffectMixin`, default priority 1000; keep it that way).
- `FishingHook.retrieve`'s loot roll has two chained MixinExtras `@ModifyExpressionValue` handlers instead of one `@Redirect`: legacy's `ExplorationFishingMixin` (priority 900, ocean notes, sees the native catch first) and fishing's `RegionalFishingMixin` (default priority).
- Cross-mod recipes use `fabric:registry_contains` on the foreign item ids rather than `all_mods_loaded`, so they stay correct when content moves between mods (boss ingredients are in legacy today).
- Repo-level `tools/` scripts still point at `src/...` paths that moved to `modules/<name>/src/...`. Only `verify-cuisine-art.py` (used by `fullCheck`) is updated; it resolves each art path in whichever module owns it. `tools/assets/cuisine.py` still writes the old single-module `Cuisine.java`/resource layout and must not be rerun as is.
- Mount token reclaim on join runs in a Fabric event phase ordered after the default phase, so OneBlock's profile restore (a default-phase `JOIN` listener) still happens first.
- `Darkspawn.onInitialize` calls the extracted mount and Noah mods' idempotent `initialize()` methods so legacy code can use their items at init time regardless of entrypoint order.
- `ascension_chapter_game_test_chapter_guardians_credit_their_own_phases_and_leave_terrain_untouched` fails when run on its own with `-PgameTestFilter` (also at the Stage 4 commit); it passes in the full suite. Use the full suite, or the whole `ascension*` set, for that test.
